# Bart — веб-ассистент

Статический сайт (без сборки): работает на GitHub Pages.

## Запуск
1. Создайте репозиторий на GitHub, загрузите в него **содержимое** этой папки (index.html в корне).
2. Settings → Pages → Source: *Deploy from a branch* → `main` / `(root)`. Через минуту сайт откроется по адресу `https://ИМЯ.github.io/РЕПО/`.
3. До подключения Firebase сайт работает в локальном режиме (чаты в браузере).

## Firebase (аккаунты и синхронизация)
1. Project settings → Your apps → Web (`</>`) → скопируйте `firebaseConfig` в `js/firebase-config.js`.
2. Authentication → Sign-in method: включите **Email/Password** и **Google**.
3. Authentication → Settings → Authorized domains: добавьте `ИМЯ.github.io`.
4. Firestore Database → Rules:
```
rules_version = '2';
service cloud.firestore { match /databases/{d}/documents {
  match /users/{uid}/{document=**} { allow read, write: if request.auth != null && request.auth.uid == uid; }
}}
```
5. Realtime Database → Rules:
```
{ "rules": { "presence": { "$uid": { ".read": "auth != null && auth.uid == $uid", ".write": "auth != null && auth.uid == $uid" } } } }
```
Почта: Firebase шлёт **ссылку** подтверждения (не код); текст письма меняется в Authentication → Templates.
Google: на мобильных вход через всплывающее окно; из встроенных браузеров (Telegram, Instagram) Google не пускает — откройте ссылку в Chrome/Safari.

## Как работают модели
Два провайдера: **Groq** и **ModelScope** (`js/config.js`, ключи в base64). Названия не зашиты: сайт берёт актуальные списки моделей и выбирает подходящие, мёртвые (404) пропускает.
- текст → Groq `gpt-oss-120b`, запасные: Llama 3.3 70B, Qwen, затем DeepSeek на ModelScope;
- код и длинные файлы → ModelScope **DeepSeek (самая новая версия из списка, V4 → V3.2…)**, запасные — Groq;
- картинки на входе → Groq vision, запасная — Qwen-VL на ModelScope;
- картинка + код/файл → два шага: vision читает картинку, потом код-модель отвечает;
- «нарисуй…» → Groq переводит запрос в английский промпт, **ModelScope Qwen-Image** рисует (асинхронная задача, до ~2 минут), запасной вариант — Pollinations; результат сохраняется на imgbb.
- Лимиты: при 429 сайт ждёт указанное время и повторяет, затем идёт к следующей модели; история обрезается под бюджет провайдера (старые файлы заменяются пометкой), чат хранится компактно (лимит Firestore 1 МБ).
Под каждым ответом показана модель. Файлы: txt/md/код/json/csv, PDF (до 40 стр.), DOCX; в чат уходит до 30 000 символов.

## Ваши иконки
Сайт сначала показывает встроенные иконки, а если в `assets/icons/` лежит `ИМЯ.png` (menu, plus, send, attachFile, camera, delete, search, copyIcon, download, close), подставляет вашу.
Скачать все 105 иконок в репозиторий: вкладка **Actions → Fetch icons → Run workflow** (список в `icons.txt`). Если Actions не даёт писать: Settings → Actions → General → Workflow permissions → Read and write.
Или положите PNG в `assets/icons/` вручную.

## Прокси для ModelScope (если картинки/DeepSeek не работают из браузера)
ModelScope может не разрешать запросы прямо со страницы (CORS). Тогда в чате появится пометка «Qwen-Image недоступен: … CORS», а DeepSeek будет пропускаться. Решение — бесплатный Cloudflare Worker: код в `proxy/worker.js` (инструкция в комментариях), адрес воркера вписать в `js/config.js` → `PROXY`.

## ModelScope: «Please bind your Alibaba Cloud account»
Если кнопка 🔧 показывает 401 с этим текстом, ModelScope не пускает к API, пока в аккаунте modelscope.cn не привязан Alibaba Cloud (Settings → Alibaba Cloud / Bind). Пока он не привязан, сайт сам отключает ModelScope: картинки рисует Flux (Cloudflare Workers AI), код и рассуждения — gpt-oss-120b на Groq. Альтернатива для кода: ключ OpenRouter в `js/config.js` → `OR_KEY` (бесплатные модели `:free`, регистрация по почте/Google, без карты).

## Работа без VPN и ключи на сервере
Запросы к Groq, OpenRouter и imgbb идут через Cloudflare Worker (`proxy/worker.js`, адрес в `js/config.js` → `PROXY`): API видит запрос с серверов Cloudflare, поэтому в странах, где Groq закрыт, VPN пользователю не нужен. Если прокси недоступен, сайт сам пробует обратиться напрямую. Firebase (вход, облако чатов) через прокси не идёт.
Перед публикацией приложения лучше убрать ключи из `js/config.js` и положить их в воркер: Settings → Variables → Secrets → `GROQ_KEY`, `OR_KEY`, `IMGBB_KEY`, `MS_KEY` — воркер подставит их сам.
Служебная проверка моделей (🔧) для пользователей скрыта: она появляется, если открыть сайт с `?debug` в адресе (там же под ответами видно, какая модель отвечала).

## Запасной текст без ключей (Workers AI)
Если ключи Groq/OpenRouter/ModelScope недействительны или закрыты, Bart отвечает через Cloudflare Workers AI на вашем воркере (маршрут `/cf/chat/completions`, нужна привязка `AI`): бесплатно, без ключей, без VPN. Это лимитированный по суткам запас (нейроны Cloudflare) и модели скромнее, чем у Groq, поэтому основной канал всё равно лучше держать рабочим.
Новый ключ Groq лучше положить в воркер: Settings → Variables and Secrets → Add → Type: Secret, имя `GROQ_KEY` → Deploy. Воркер подставит его сам, а строку `groq` из `js/config.js` можно удалить. Недействительный ключ в сообщениях пользователю не показывается.

## Библиотеки в корне и сеть без VPN
Все библиотеки (marked.min.js, purify.min.js, highlight.min.js, github-dark.min.css, jszip.min.js, xlsx.full.min.js, html2pdf.bundle.min.js, pptxgen.bundle.js, pdf.min.js, pdf.worker.min.js, mammoth.browser.min.js) и Firebase SDK (`firebase.js`) лежат в корне репозитория рядом с `index.html` и грузятся с самого сайта, поэтому ему не нужны внешние CDN (cdnjs и др. у части провайдеров недоступны). Логотип — `logo.svg` (замените файл своим). Если основной прокси недоступен, можно добавить запасные в `js/config.js` → `PROXY2: ['https://второй-воркер…']`; сайт сам выберет рабочий. Запрос, который молчит дольше 12 секунд, пропускается.
Чтобы понять, что именно недоступно у пользователя: откройте сайт **без VPN** с `?debug` в адресе, нажмите 🔧 — сверху будет список доступных и заблокированных адресов.

## Удаление фона, PDF, интерфейс
- «удали фон» + приложенное фото: однотонный фон (логотипы, иконки, предметка) убирается мгновенно в браузере; сложный фон (фото) — нейросеть `@imgly/background-removal` (скачивается с cdn.jsdelivr.net и staticimgly.com, ~40 МБ при первом запуске, потом кэш).
- PDF собирается в браузере: обычный документ из Markdown/HTML или презентация (HTML со `<section class="slide">`, альбомная страница на слайд).
- Дизайн в духе Claude: светлая и тёмная темы (кнопка в сайдбаре), пустой чат с приветствием и полем ввода по центру. Цвета и шрифты — переменные в начале `css/style.css`.

## Лимиты и стабильность
В запрос идут только **последние 8 сообщений**; свежее — целиком, старое — сокращённо. Если провайдер отвечает «слишком большой запрос» (413/429 по токенам), сайт читает цифры из ошибки и сам сжимает запрос. Запросы к провайдерам идут с паузой (Groq ≈ 1 в 2 сек), ответ печатается плавно, скролл не дёргается, если вы листаете вверх. Кнопка 🔧 в сайдбаре проверяет Groq, прокси, DeepSeek, Qwen-Image и запасной Flux; `?debug` в адресе показывает под ответом, какая модель отвечала.

## Файлы от Bart
Всё, что Bart выдаёт файлом (html, pdf, docx, xlsx, pptx, csv, код, ZIP из нескольких файлов), показывается карточкой с кнопками «Открыть / Скачать». PDF/DOCX/XLSX/PPTX собираются прямо в браузере из текста, который пишет модель. Обрезанные по длине ответы Bart сам продолжает (до 6 раз).

## Вложения
Картинки можно отправить **как фото** (сжимаются вдвое, идут альбомом) или **как файл** (оригинал без сжатия): плашка «Фото/Файл» на миниатюре переключает режим. Остальные форматы — см. ниже. Перетаскивание файлов на окно и вставка из буфера работают.

## Файлы, ZIP, голос
- Читает: PDF (текст с сохранением строк таблиц; сканы без текста отправляются как картинки страниц в vision), DOCX, DOC (приблизительно), TXT, RTF, ODT, HTML, EPUB, CSV, XLSX/XLS/ODS (значения ячеек по листам, формулы не показываются), JSON, XML, YAML, TOML, PPTX (текст слайдов), MD, IPYNB, ZIP (список файлов + текст кода внутри), любой текстовый файл и код; картинки JPG/PNG/GIF/WEBP.
- В чат уходит до 30 000 символов файла, дальше текст обрезается.
- Создание ZIP: попросите «создай проект …» — Bart выдаёт каждый файл отдельным блоком с именем, под ответом появляется кнопка «ZIP».
- Голос: кнопка микрофона записывает речь, текст вставляется в поле ввода (распознавание Whisper). Нужен HTTPS (GitHub Pages подходит) и разрешение на микрофон.

## Безопасность ключей
Ключи в `js/config.js` видны любому, кто откроет сайт. Для публичного сайта их стоит заменить на ключи с лимитами или вынести на свой прокси.

## Призрачные чаты, шаринг, установка
- **Призрак** (иконка 👻 в шапке и рядом с «Новый чат»): чат живёт только в памяти, не пишется ни в облако, ни в localStorage и исчезает при перезагрузке страницы. В списке слева помечен значком.
- **Поделиться** (иконка в шапке): создаётся ссылка на снимок диалога без ваших вложений-текстов. Получатель открывает её без входа в аккаунт, видит чат только для чтения и может «Продолжить в своём чате».
  Чтобы ссылки были короткими и работали для любых чатов, добавьте в правила Firestore (Firebase → Firestore → Rules):
  ```
  match /shared/{id} {
    allow read: if true;
    allow create: if request.auth != null;
    allow update, delete: if false;
  }
  ```
  Без этого правила сайт делает ссылку-снимок прямо в адресе (`#c=…`, до ~60 КБ) — для небольших чатов этого достаточно.
- **Установка (PWA)**: на ПК (Chrome/Edge) в адресной строке появится значок установки, на Android — «Установить приложение» в меню; кнопка есть и в боковой панели. На iPhone: Поделиться → «На экран Домой». Данные общие с сайтом, чаты синхронизируются с аккаунтом. Иконка ПК — логотип сайта, иконка телефона — maskable-иконка из `manifest.webmanifest`.
- **APK для Android**: откройте pwabuilder.com, вставьте адрес сайта, выберите Android → Download; получите APK/AAB (подпись и публикация в Google Play — на стороне разработчика).

## «Мозги» Bart (v2)
- **Зрение.** Раньше цепочка vision могла целиком умереть (одна устаревшая модель + фильтр отсекал Llama 4 Scout), и на любое фото приходило «Не получилось ответить». Теперь список строится из живых `/models` (Groq → бесплатные vision-модели OpenRouter → Workers AI на воркере → ModelScope). Если зрение недоступно совсем, Bart честно отвечает по тексту сообщения и говорит, что картинку не увидел, а не падает с ошибкой.
- **Знает свои возможности.** В системный промпт добавлен блок «ЧТО ТЫ УМЕЕШЬ / ЧЕГО НЕ УМЕЕШЬ» (файлы, картинки, создание файлов, нет интернета и запуска кода), а к каждому запросу добавляется контекст: дата, что приложено к сообщению.
- **Не путается в длинных чатах.** Всё, что выпало из окна последних 8 сообщений, сжимается в скользящее резюме (`chat.sum`), которое подставляется в системный промпт.
- **Думает перед кодом.** Для запросов кода сначала строится скрытый план (требования → подход → риски), потом идёт основной ответ. Для сложных текстовых задач включается высокое усилие рассуждения.
- **Проверяет свой код.** Кроме проверки синтаксиса JS/JSON, HTML-страница на ~2 с запускается в скрытой песочнице: кликаются кнопки, нажимаются клавиши, ловятся ошибки вроде `x is not defined` и «белого экрана». Найденные ошибки Bart исправляет сам до показа ответа. Проверка пропускается для страниц с локальными файлами (`script.js`, `style.css`) и с бесконечными циклами.
- Диагностика 🔧 (`?debug`) проверяет до 8 vision-моделей — по ней видно, какая реально отвечает.

## Работа без VPN (v3)
**Почему без VPN модели молчали.** По замерам с домашнего московского IP (Habr, 1 октября 2026) Groq, OpenRouter и Together отвечают 403 по региону, а DeepSeek, Mistral, Z.ai, Qwen, Kimi и MiniMax — пускают. Воркер Cloudflare выполняется на узле рядом с пользователем, поэтому без VPN он может выходить в сеть с российского узла и получать тот же 403. Остаётся слабая запасная модель Workers AI — отсюда «Конечно, исправлю…» и плохой код.

Что сделано в коде:
- 403 больше не «убивает» провайдера до конца сессии: пауза 3 минуты, затем повтор; при 403 через прокси пробуется следующий адрес (`PROXY2`, затем напрямую).
- Новые провайдеры без региональных блокировок: **DeepSeek, Mistral, Z.ai (GLM), Qwen (Alibaba Model Studio)**. Включаются сами, если на воркере есть секрет (`DEEPSEEK_KEY`, `MISTRAL_KEY`, `ZAI_KEY`, `QWEN_KEY`) или ключ в `js/config.js → CFG` (`deepseek`, `mistral`, `zai`, `qwen`, в base64). Для кода первым идёт DeepSeek, для картинок — Mistral/Qwen-VL.
- Если все ключи недоступны, пользователь видит понятную причину (регион/доступ), а не «Не получилось ответить».

Что нужно сделать на стороне Cloudflare (кодом это не решается):
1. Воркер → Settings → General → Placement → **Smart** (или `proxy/wrangler.toml`, `placement.region`). Через 10–15 минут проверьте без VPN.
2. Привяжите Alibaba Cloud к аккаунту modelscope.cn (см. раздел выше): ModelScope доступен из РФ и даёт DeepSeek/Qwen бесплатно — это самый дешёвый канал без VPN.
3. По желанию добавьте секрет `DEEPSEEK_KEY` (платный, но очень дешёвый) и/или `MISTRAL_KEY`, `ZAI_KEY`.
4. Проверка: откройте сайт без VPN с `?debug` → 🔧: видно, какие модели отвечают.

## Интерфейс (v3)
- Режим «версия для ПК» на телефоне: экран входа не схлопывается при зуме (раньше `--vh` пересчитывался по visualViewport и сжимал экран).
- Ответ не пересоздаётся целиком при стриме: обновляется только последний блок, готовые блоки кода, выделение и прокрутка не сбрасываются; подсветка кода кэшируется.
- У карточки файла появилось «Показать код» — код можно читать прямо в чате.
